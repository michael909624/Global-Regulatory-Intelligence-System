business_dimensions 输出（八维 L3）
────────────────────────────────────────
JSON 数组，元素来自八个 L3 代码：
   售前：RD / PROD / CERT
   售中：IMPORT / RETAIL / USE
   售后：ENFORCE / EOL

读完原文后，问自己一个问题：
   "这条法规会对我司哪些业务环节产生影响？"
所有触及的维度都填上——一条法规可以同时落在 1-3 个 L3 维度。

校准案例（理解"调性"，不要做模式匹配）：
   电池技术规范 GB 43854             → ["RD"]
   RoHS / REACH 物质限制             → ["PROD"]
   强制 CCC 认证流程改革             → ["CERT"]
   关税调整 / 反倾销公告             → ["IMPORT"]
   零售前年龄验证 / 强制安全警示     → ["RETAIL"]
   补贴 / 以旧换新 政策              → ["RETAIL"]
   道路交通法 + 强制保险 + 限速     → ["USE"]
   共享出行运营许可                  → ["USE"]
   Safety Gate 召回令                → ["ENFORCE"]
   行政罚款决议                      → ["ENFORCE"]
   EPR 电池回收义务 / 押金返还       → ["EOL"]
   产品责任险 / 召回成本             → ["EOL"]

跨维度复合案例：
   CRA 网络安全设计 + conformity 评定        → ["RD", "CERT"]
   电池护照（原料披露 + 强制注册）           → ["PROD", "CERT"]
   危险品运输（生产合规 + 海关清关）         → ["PROD", "IMPORT"]
   召回 + 同步罚款                           → ["ENFORCE"]（一个动态）
   EU Battery Reg 主条 → 含技术规范 + EPR    → ["RD", "EOL"]（条文上是两段，
        分析上保留双维度让 reporter 进两个 sheet 给研发部和 EHS 部门）

不相关：仅当八维全部不触及，且原文与 LEV 业务无任何交集
   （如四轮乘用车专项召回、医疗建筑、船舶通信、卫浴配件等）
→ business_dimensions = []，affected_products = "不相关"。

⚠️ 抓错原文兜底：原文与标题严重不符时（标题写 LEV 但原文讲数据中心/医疗/家居），
按原文实际内容判定，business_dimensions 通常 []，
并在 business_impact 首条标注："原文与标题不符，建议人工复核 source_url"。

⚠️ researcher 阶段可能预填了 business_dimensions（轻量预判），但你应基于原文
   重新判定——以原文为准，不照搬上游标签。
